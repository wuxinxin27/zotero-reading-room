## 已实现的阅读流程

实际论文检查发现，单纯汇总模型挑出的短引文仍会漏掉种子、成本和表格列名。协议 v4 因而在综合中优先加入最多 12 段、每段最多 1000 字符的已读原文上下文，再分配候选发现与模型图表引用。它们用于复核报告信息及数值条件，不是自动事实裁决；仍共享原有综合预算、保持原请求次数。表格布局无法从提取文字确认时，应说明映射未核实，不能编造数值矛盾。

1. **规划来源覆盖。** `Core.planAnalysis()` 先扫描全部可用提取文字。总量不超过 120000 字符时全部保留；超出时依据标题线索及全文位置分布选取，保留开头与末尾位置，参考文献后仍继续扫描附录。标题线索是启发式提示，不是经过核验的目录或语义章节识别。
2. **按包提取候选发现。** 独立来源摘录保留页索引、原始位置及章节线索，再装入每包最多 16000 个原文字符、最多 12 包。一个包可以跨多个物理页，但各摘录独立；引文只在本次真正提交的单条摘录及对应页上核对，不能跨摘录拼接或引用未提交窗口。六维解释和贡献子类型继续沿用现有结构。
3. **从已匹配摘录综合。** 多包时最多再请求一次模型。综合输入最多 48000 字符，其中最多 48 条、共 28000 字符引文；按维度轮转，并优先补充较少覆盖的证据包和章节线索，图表文字候选最后加入。候选发现的 `evidenceIds` 与保留摘录一起准入，预算不足时不会留下悬空 ID 或失去全部来源的候选发现。候选解释不作为原文证据，最终维度及叙述的引文仍需匹配单条获准综合摘录。另保留阅读阶段已匹配的图表文字候选，它们可能未进入综合输入，不能当作综合论断已经得到支持的证明。

例如，虚构的 20 页、76000 字符测试提交全部原文，使用 5 个阅读包与 1 次综合。请求数由实际文字量及规划结果决定，不承诺每篇都是 6 次。没有额外的审稿模型；仅 `MODEL_JSON_INVALID` 允许对同一任务重新生成一次，可能增加调用与费用，不补造 JSON 语法。四种服务协议、凭据保护、取消、完成状态检查及失败保留旧缓存继续适用。

默认学术指令现在要求解释问题与已有方法缺口、具体增量、输入输出、模块关系、方程符号、目标、约束和假设；按原文保留数据集、划分、指标、比较数值、基线资源条件、消融、种子或不确定性、算力或延迟、失败条件及复现细节。未报告不等于未执行、效果为零或方法失败；无关领域检查项不强填。可微强化学习、世界模型与机器人问题只在相关论文中讨论。

当前固定输出协议为 `"4"`，指导约 3200 中文字符的分析叙述，证据充分的维度可约 800 字符，缺乏依据时不凑篇幅。它不是最低字数、硬性 token 预算或质量评分。Anthropic 与 Gemini 输出额度均保持 8192 token；重复的有效提示词、JSON 结构及服务约束仍可能占用上下文或导致截断。

## 当前侧栏展示

侧栏保留论文概览、六维分析及“精读重点”（原“阅读路径”）。精读重点应提出具体核对问题，并指向可用的章节、图或表；例如检查目标函数假设、基线条件或失败边界。这是现有 `service.js` 默认 `readingGuide` 指令的要求，本轮未修改提示词、协议版本或 `readingGuide` / `figureTableReferences` 等数据字段，也不重写旧缓存；改名不证明模型输出质量提高。

笔记下方的固定五项人工核对框及其自动保存、Markdown 固定核对清单均已移除，用户自己写在笔记中的复选项保留。独立“论文图表”卡片已移除，正文中的证据引用、原页导航及按需内联原页预览保留；模型仍不理解图表图像。后端图表文字候选、校验、缓存和 JSON 导出不变。

## 覆盖信息怎样理解

新分析的 `coverage.analysisPlanVersion` 为 `1`，覆盖信息随结果保存在本地。下表解释保存及 JSON 导出的字段，不表示侧栏仍提供范围详情或章节矩阵。兼容字段 `chunksAnalyzed` / `chunksAvailable` 现在表示证据包数量，不能当作 PDF 页数；历史结果保留原含义，不补写新字段。

| 字段 | 含义与限制 |
| --- | --- |
| `extractedCharacters` / `analyzedCharacters` / `ratio` | 可用提取文字量、已提交原文量及其比例；不衡量模型是否理解、保留或正确解释这些文字 |
| `selectionStrategy` | `complete-source` 表示全部可用提取文字被选取；`section-position-heuristic` 表示按标题线索和位置抽样 |
| `sections` | 各 `hint` 的 `totalCharacters` 与 `selectedCharacters`；`unknown` 表示没有识别出标题线索，不表示论文没有该章节 |
| `omittedCharacters` | 未提交的提取文字字符数；不统计 PDF 中根本没被提取出来的内容 |
| `sourceExcerpts` | 提交的独立原文摘录数量，不等于页数或引文数量 |
| `packetsAnalyzed` / `packetsAvailable` | 已完成与本次计划内的证据包数，不代表全文所有可能窗口 |
| `synthesisExcerpts` | 综合阶段实际收到的已匹配引文数；综合不会重收全部原文 |
| `completeDocument` | 需页边界可确认、提取页数与总页数一致且提交全部提取文字；仍不证明文字提取完整或论文被完整理解 |

侧栏只保留已提交／可提取文字量及部分覆盖、提取和分页限制的简要说明，不再显示“选中文字范围”详情或章节矩阵。标题线索仍为启发式元数据，不是已核验目录。覆盖说明不会请求模型；移除详情不改变来源选取或保存字段，也不把全部提取文字已提交说成论文已读懂。

## 如何应用到已有论文

没有保存自定义提示词时，新任务使用新默认。已保存的自定义提示词保留原文；需要新默认时，先自行备份，再在提示词设置选择“恢复默认”并保存，这会重置全部三项提示词。之后对目标论文显式选择“重新分析”。保存提示词、打开论文或点击普通分析均不会自动刷新旧缓存，无需手动删除缓存；失败或取消保留旧结果。

## 尚未证明的内容

当前检查覆盖虚构文字的来源规划、预算、页边界、综合证据关联及服务回归，详见 [TESTING.md](TESTING.md)。用户重新配置凭据后，当前论文的实际模型流程已成功保存：20 页可提取文字全部提交，5 次阅读和 1 次综合正常结束，46 处引文/图表候选通过文字匹配检查。内容复核促成了本例表格误判、贡献枚举等局部修正，但仍有待核实项；这不是受控准确率评估，也不能把文字全部提交当作全文被正确理解。

引文匹配只证明文字存在于提交来源，不验证其是否支持结论。程序没有实现独立语义蕴含评估、自动基线公平性判定、数值/单位/证明核验、代码执行或复现实验；这些是提示词提出的阅读问题，仍需读者核查。没有 OCR、图表视觉理解、外部文献检索或独立审稿调用；扫描、公式、表格和分页提取可能不完整。覆盖全部提取文字也可能在综合预算内丢失细节，不能标为“论文已完全核查”。
