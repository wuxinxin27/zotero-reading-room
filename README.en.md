# Reading Room for Zotero

[中文说明](README.md) · [Privacy](PRIVACY.md) · [AI prompts](docs/AI-PROMPTS.md) · [Security](SECURITY.md)

A local-first, experimental Zotero 10 reading companion in the right sidebar of Zotero's normal PDF reader. Default entry points open or focus the reader and Reading Room section without opening a separate top-level Reading Room window. The latest released version remains **0.2.0**; the sidebar, editable prompts, batch analysis, paper chat and status tags described below are **Unreleased** development changes with core sidebar flows checked on Windows Zotero 10.0.7; see the test checklist for remaining coverage. Zotero **10.0–10.*** is the declared range, with **10.0.7** as the initial live-test target. Synthetic automated tests do not establish live compatibility. See the [test checklist](docs/TESTING.md). This project does not claim inclusion in the official Zotero add-ons directory.

- Manually select **Unread / To read / Reading / Read / Parked**. This saves local state and attempts to set exactly one of `阅读室/未读`, `阅读室/待读`, `阅读室/在读`, `阅读室/已读`, or `阅读室/搁置` on an editable parent item, retaining other tags. Analysis and chat never change reading status or tags.
- Record local notes and a reading checklist; show bibliographic metadata, local PDFs, and note/annotation counts.
- Browse the original library, collection and subcollection hierarchy, including empty collections. Filter direct collection members, search/page within scope and switch among global focused-paper chips. Navigation can be collapsed to give sidebar content more room.
- Read source PDFs in Zotero's normal reader with analysis, notes and paper chat in its right sidebar. Evidence buttons jump to the current attachment's physical PDF pages ; native navigation targets pages and does not promise literal text highlighting. Missing page numbers are never guessed.
- AI analysis returns a natural overview, a reading guide, six source-backed dimensions, and text references to figures and tables. Figure cards lazily render the “source page containing the reference”; they do not claim a precise crop or visual interpretation.
- OpenAI-compatible, Anthropic Messages, Google Gemini, and native Ollama configurations are independent from analysis. Analysis is cached per paper and attachment and is reused without a model request; only an explicit reanalysis sets `force: true`.
- View, edit in full, and restore all three prompts: analysis system prompt, multi-chunk synthesis instruction, and paper-chat system prompt. Saving prompts makes no model request and does not invalidate existing analysis. Use explicit reanalysis to apply a new analysis prompt to cached papers. See the [verbatim defaults and output contract](docs/AI-PROMPTS.md).
- Select explicit papers, the current page, or the current filtered scope, then review up to 1000 targets before starting batch analysis. It runs sequentially with per-paper progress, cache reuse, cancellation and failed-item retry. Reanalysis requires a separate choice.
- Ask about the current PDF without first running analysis. Only Send submits the question, bounded source excerpts and limited history. Successful question/answer pairs and validated citations are stored locally per paper and attachment; history loading makes no model request. Unsupported answers are marked unverified/information insufficient.
- Explicitly export JSON/Markdown, create an analysis note, or save a reading-state snapshot to a plugin-owned note in a personal library. Apart from manual status tags, parent fields and existing user notes are preserved; group-library note writes are forbidden.

Build the development branch or use its commit-specific CI artifact for these unreleased features. For a released version, download its `.xpi` and `SHA256SUMS` from [Releases](https://github.com/wuxinxin27/zotero-reading-room/releases), verify the checksum, then use **Tools → Plugins → Install Plugin From File** in Zotero (the option may be under the gear menu). Select a paper and open Reading Room through its menu, context-menu, item-pane or reader-toolbar entry to focus the normal reader sidebar. Without a local PDF, status and notes remain available in the item sidebar. Zotero 10 requires an update URL; the build generates versioned `updates.json` with the XPI SHA-256 for Release distribution. Update checks follow Zotero settings; upgrading between released versions is not yet independently verified.

No model request, attachment download or endpoint discovery runs at startup. Selecting or switching papers also makes no model request and can show a saved analysis without a configured key. The independent model settings accept four protocols and a base URL or the corresponding legacy full request URL; endpoint normalization is handled by the backend, as documented in [API providers](docs/API-PROVIDERS.md). The default OpenAI-compatible base is `http://127.0.0.1:11434/v1`; analysis uses its `/chat/completions` route, and the legacy full request URL is also accepted.

Model discovery begins only after you open AI settings. Changes to the endpoint, protocol, or key are debounced by about 700ms; superseded requests are cancelled and late results are ignored. The returned list is searchable and manual model IDs remain available. Unsupported listing endpoints, authentication failures, timeouts, and empty lists show a clear fallback message. The plugin does not ship a list of supposedly available model names, and it does not start or download models.

Loopback endpoints can discover models automatically. Remote HTTPS discovery requires a separate explicit permission and does not send a PDF or paper text. Analysis and chat require paper-text permission before excerpts are sent. Group-library remote analysis and chat are blocked. Each remote permission is bound to both origin and provider, and changing either revokes the old permission and clears unsubmitted key input. Keys are not saved by default. With explicit opt-in, Zotero `OSKeyStore` encrypts a key and `Services.logins` stores only the encrypted value; the sidecar contains non-secret configuration and the UI reports only whether a key exists. A local model service may have its own logging or network behavior.

Analysis reads at most 12 chunks / 120000 characters, followed by at most one synthesis request containing bounded findings and previously checked excerpts. Chat accepts a question of up to 6000 characters and sends at most 8 source excerpts / 24000 characters plus the latest 10 history messages / 12000 characters. History is context, not source evidence; neither extraction nor excerpt matching establishes full-paper understanding or visual interpretation. Failed or cancelled chat requests do not append partial pairs. Batch requests, reanalysis, chat and long custom prompts can increase token usage and provider charges; character limits do not guarantee a token budget or cost. Do not put credentials into prompts, questions or notes.

Batch targets are frozen at start and never expand with navigation or filters. The UI locks model/prompt settings while running, and the backend snapshots prompts; changes to endpoint, model, permissions or credentials through another caller stop later sends. Individual failures do not stop subsequent targets. Cancellation retains completed results and old caches. Queue progress belongs to the current service session and does not automatically resume after restart.

Reading state, focus marks, notes, checklists, excerpts, analysis caches, all three prompts, tag-sync outcomes and successful per-attachment conversations live in `reading-room/state-v1.json` inside the Zotero data directory, with a previous-version `.bak`. This sidecar is local and does not merge automatically across devices. Manual status changes save locally first, then replace only the other four reserved status tags on editable personal or group items. All unrelated tags, including other `阅读室/` tags, remain intact. Permission, unsaved-edit, missing-API or save failures retain local state and show a sync warning; select the status again to retry. Native tags and explicitly created personal-library plugin notes may sync through Zotero's own settings. Tags are not imported back into local state, and state-note synchronization is an explicit snapshot rather than automatic two-way merge or restore. Uninstalling retains the sidecar, tags and created notes; export/back up before manually removing them.

This unreleased work has no OCR, visual figure interpretation, proof checking or code verification. Earlier standalone-workspace PDF/page-preview checks on Zotero 10.0.7 do not establish acceptance of this sidebar migration; native lifecycle, layout and other host versions still need live verification. Page references use physical PDF pages and can differ from printed page labels. Candidate citations and model inferences require manual review. Only the reader can confirm a full review.

Build with **Node.js 22+**, without npm dependencies or installation:

```sh
npm test
npm run check
npm run build
```

Outputs: `dist/zotero-reading-room-0.2.0.xpi` (a deterministic standard ZIP containing runtime addon sources only) plus `dist/SHA256SUMS` and `dist/updates.json`. Tests use synthetic fixtures only. Never submit personal library data, profile paths, titles, excerpts, screenshots or keys.
