# Reading Room for Zotero

[中文说明](README.md) · [Privacy](PRIVACY.md) · [AI prompts](docs/AI-PROMPTS.md) · [Engineering reading](docs/ENGINEERING-READING.md) · [Security](SECURITY.md)

A local-first, experimental Zotero 10 reading companion for the paper currently open in Zotero's normal PDF reader. Its right sidebar provides single-paper AI analysis, chat, editable prompts, notes and manual status tags. Zotero handles library browsing and paper switching; the plugin does not enumerate the complete library. Tools, selected-item context menus and reader-toolbar entry points open or focus the normal reader and its section without creating a top-level Reading Room window. The latest released version remains **0.2.0**; these are **Unreleased** development changes. Core current-paper flows have been checked on Windows Zotero 10.0.7; see the test checklist for remaining coverage. Zotero **10.0–10.*** is the declared range, with **10.0.7** as the initial live-test target. Synthetic tests do not establish live compatibility. See the [test checklist](docs/TESTING.md). This project does not claim inclusion in the official Zotero add-ons directory.

- Manually select **Unread / To read / Reading / Read / Parked**. This saves local state and attempts to set exactly one of `阅读室/未读`, `阅读室/待读`, `阅读室/在读`, `阅读室/已读`, or `阅读室/搁置` on an editable parent item, retaining other tags. Analysis and chat never change reading status or tags.
- Record free-form local notes; show bibliographic metadata, local PDFs, and note/annotation counts. The fixed five-item manual checklist and its autosave are removed, and Markdown no longer adds that fixed list. Checkbox Markdown written in your notes is preserved.
- Bind the sidebar to the exact current reader tab and PDF attachment, keeping different PDFs under the same paper distinct. Library-list selections do not mount a Reading Room view.
- Read source PDFs in Zotero's normal reader with analysis, notes and paper chat in its right sidebar. Evidence buttons jump to the current attachment's physical PDF pages ; native navigation targets pages and does not promise literal text highlighting. Missing page numbers are never guessed.
- AI analysis returns an overview, “Close-reading focus” (精读重点), and six evidence-linked dimensions. The focus should pair concrete verification questions with available sections or figure/table references, as the existing default prompt already requests. It also asks about engineering mechanisms, equations, assumptions, metrics, baselines, ablations, failures and reproducibility reporting. About 3200 Chinese narrative characters is flexible guidance, not a length or quality guarantee. Inline evidence citations, page navigation and on-demand source-page previews remain; standalone figure/table cards are removed. The model has no visual figure understanding.
- Plan source coverage, extract candidate findings in bounded packets, then synthesize from matched excerpts. Up to 120000 source characters are retained in full; larger sources are sampled across heading hints and document positions, including the end. The sidebar keeps a compact submitted/extracted-text summary and partial/extraction limitations, without the detailed range/section panel. Submitting all extracted text does not establish full-paper understanding. See the [public-project comparison and implemented changes](docs/ENGINEERING-READING.md).
- OpenAI-compatible, Anthropic Messages, Google Gemini, and native Ollama configurations are independent from analysis. Analysis is cached per paper and attachment and is reused without a model request; only an explicit reanalysis sets `force: true`.
- View, edit in full, and restore all three prompts: analysis system prompt, multi-chunk synthesis instruction, and paper-chat system prompt. Each effective system prompt also appends a fixed task-specific output contract; expand the read-only contract and complete effective prompt in the editor to inspect them. Saving prompts makes no model request and does not invalidate existing analysis. Use explicit reanalysis to apply a new analysis prompt to cached papers. See the [verbatim defaults and output contract](docs/AI-PROMPTS.md).
- User messages also carry an explicit task and the same frozen effective prompt for gateway compatibility, increasing input usage. Anthropic and Gemini output allowances remain 8192 tokens; invalid JSON, invalid analysis structure, and service truncation have distinct errors.
- Ask about the current PDF without first running analysis. Only Send submits the question, bounded source excerpts and limited history. Successful question/answer pairs and validated citations are stored locally per paper and attachment; history loading makes no model request. Unsupported answers are marked unverified/information insufficient.
- Explicitly export JSON/Markdown, create an analysis note, or save a reading-state snapshot to a plugin-owned note in a personal library. Apart from manual status tags, parent fields and existing user notes are preserved; group-library note writes are forbidden.

Build the development branch or use its commit-specific CI artifact for these unreleased features. For a released version, download its `.xpi` and `SHA256SUMS` from [Releases](https://github.com/wuxinxin27/zotero-reading-room/releases), verify the checksum, then use **Tools → Plugins → Install Plugin From File** in Zotero (the option may be under the gear menu). Open a PDF in Zotero and use Tools or the reader toolbar to focus its sidebar; the selected-paper/PDF context menu can open one normal PDF reader. Missing or mismatched PDF contexts do not mount the section or fall back to another attachment. Zotero 10 requires an update URL; the build generates versioned `updates.json` with the XPI SHA-256 for Release distribution. Update checks follow Zotero settings; upgrading between released versions is not yet independently verified.

No model request, attachment download or endpoint discovery runs at startup. Selecting or switching papers also makes no model request and can show a saved analysis without a configured key. The independent model settings accept four protocols and a base URL or the corresponding legacy full request URL; endpoint normalization is handled by the backend, as documented in [API providers](docs/API-PROVIDERS.md). The default OpenAI-compatible base is `http://127.0.0.1:11434/v1`; analysis uses its `/chat/completions` route, and the legacy full request URL is also accepted.

Model discovery begins only after you open AI settings. Changes to the endpoint, protocol, or key are debounced by about 700ms; superseded requests are cancelled and late results are ignored. The returned list is searchable and manual model IDs remain available. Unsupported listing endpoints, authentication failures, timeouts, and empty lists show a clear fallback message. The plugin does not ship a list of supposedly available model names, and it does not start or download models.

Loopback endpoints can discover models automatically. Remote HTTPS discovery requires a separate explicit permission and does not send a PDF or paper text. Analysis and chat require paper-text permission before excerpts are sent. Group-library remote analysis and chat are blocked. Each remote permission is bound to both origin and provider, and changing either revokes the old permission and clears unsubmitted key input. Keys are not saved by default. With explicit opt-in, Zotero `OSKeyStore` encrypts a key and `Services.logins` stores only the encrypted value; the sidecar contains non-secret configuration and the UI reports only whether a key exists. A local model service may have its own logging or network behavior.

Analysis selects at most 120000 source characters and packs independent excerpts into at most 12 packets of 16000 source characters each. A packet can span multiple physical pages; selection is no longer limited to the beginning. Multiple packets use at most one synthesis request, bounded to 48000 input characters, including at most 48 matched quotations / 28000 quotation characters and linked candidate findings. There is no extra reviewer model or automatic repair/retry call. Chat accepts a question of up to 6000 characters and sends at most 8 source excerpts / 24000 characters plus the latest 10 history messages / 12000 characters. History is context, not source evidence; neither extraction nor excerpt matching establishes full-paper understanding or visual interpretation. Failed or cancelled chat requests do not append partial pairs. Reanalysis, chat and long custom prompts can increase token usage and provider charges; character limits do not guarantee a token budget or cost. Do not put credentials into prompts, questions or notes.

Saved custom prompts are retained. To adopt the new defaults, back up your custom text, restore defaults and save (this resets all three prompts), then explicitly reanalyze a cached paper. There is no need to delete caches. This pipeline has synthetic source-planning and service regression coverage; current real-paper/model success rates and scholarly quality remain unverified. See the [validation record](docs/TESTING.md). PaperQA and selected scientific skills inform the design; no external skill, model or heavy PDF parser is installed or executed.

Legacy focus fields and backend catalog/batch APIs remain for compatibility, with no current UI entry point or background invocation. This change does not migrate or delete old data.

Reading state, notes, excerpts, analysis caches, all three prompts, tag-sync outcomes and successful per-attachment conversations live in `reading-room/state-v1.json` inside the Zotero data directory, with a previous-version `.bak`. Legacy `checklist` data is retained without migration or cleanup, including in JSON exports and explicit native state-note snapshots. Backend figure candidates, validation, caches and JSON exports also remain. This UI simplification does not change prompts or the output contract or refresh cached results; it does not establish improved model quality. This sidecar is local and does not merge automatically across devices. Manual status changes save locally first, then replace only the other four reserved status tags on editable personal or group items. All unrelated tags, including other `阅读室/` tags, remain intact. Permission, unsaved-edit, missing-API or save failures retain local state and show a sync warning; select the status again to retry. Native tags and explicitly created personal-library plugin notes may sync through Zotero's own settings. Tags are not imported back into local state, and state-note synchronization is an explicit snapshot rather than automatic two-way merge or restore. Uninstalling retains the sidecar, tags and created notes; export/back up before manually removing them.

This unreleased work has no OCR, visual figure interpretation, proof checking or code verification. Earlier standalone-workspace PDF/page-preview checks on Zotero 10.0.7 do not establish acceptance of this sidebar migration; native lifecycle, layout and other host versions still need live verification. Page references use physical PDF pages and can differ from printed page labels. Candidate citations and model inferences require manual review. Only the reader can confirm a full review.

Build with **Node.js 22+**, without npm dependencies or installation:

```sh
npm test
npm run check
npm run build
```

Outputs: `dist/zotero-reading-room-0.2.0.xpi` (a deterministic standard ZIP containing runtime addon sources only) plus `dist/SHA256SUMS` and `dist/updates.json`. Tests use synthetic fixtures only. Never submit personal library data, profile paths, titles, excerpts, screenshots or keys.
