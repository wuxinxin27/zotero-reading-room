# Reading Room · 论文阅读室

[English](README.en.md) · [隐私](PRIVACY.md) · [提示词](docs/AI-PROMPTS.md) · [工科阅读](docs/ENGINEERING-READING.md) · [安全](SECURITY.md) · [开发与测试](docs/DEVELOPMENT.md)

面向 Zotero 10 的本地优先论文阅读插件：只辅助 Zotero 正常 PDF 阅读器中当前打开的论文，在右侧栏提供可回查的 AI 解读、笔记、阅读状态标签及论文对话。论文查找、收藏夹管理和切换交给 Zotero；插件不枚举完整文库。工具菜单、所选条目右键和 PDF 工具栏入口打开或聚焦正常 PDF 阅读器及侧栏，不另开顶层阅读室窗口。

当前已发布版本仍为 **0.2.0，实验版**；下面的当前论文侧栏、提示词、对话与状态标签属于 **Unreleased** 开发改动。本轮核心流程已在 Windows Zotero 10.0.7 验证；未覆盖场景见验证清单。声明兼容范围为 Zotero 10.0–10.*，初始验证目标为 **Zotero 10.0.7**；自动测试使用虚构宿主适配器，不能替代 Zotero 实机验证。实机项目见[验证清单](docs/TESTING.md)。本项目尚未声称收录于 Zotero 官方插件目录。

## 可以做什么

- 五种人工选择的阅读状态：**未读 / 待读 / 在读 / 已读 / 搁置**。手动选择后保存本地状态，并在可编辑条目上同步对应的 `阅读室/未读`、`阅读室/待读`、`阅读室/在读`、`阅读室/已读` 或 `阅读室/搁置` 标签，保留其他标签。AI 分析与对话不会自动改状态或标签。
- 侧栏严格绑定当前 PDF 标签及附件；在 Zotero 中切换论文，同一论文的不同 PDF 也分别关联分析缓存与对话。文库列表不挂载阅读室界面。
- 原文沿用 Zotero 正常 PDF 阅读器，插件内容位于右侧栏。引文按钮跳到当前附件的物理 PDF 页；原生导航定位到页，不承诺逐字高亮；未知页码不会猜成第 1 页。
- AI 解读呈现论文概览与“精读重点”，后者应结合可定位的章节或图表提出具体核对问题，并保留**研究问题、新颖性、贡献、与前人工作的关系、优势与适用边界、技术独特之处**六维证据。现有默认指令关注工科机制、假设、方程、实验指标、基线、消融、失败边界与复现报告；约 3200 中文字符是弹性叙述指导，不是质量或字数保证。正文中的证据引用及页跳转保留，按需内联预览的是引用所在原文页；侧栏不再单列“论文图表”卡片。
- 先规划来源覆盖、按证据包提取候选发现，再以已匹配摘录综合。120000 字符内保留全部提取文字，超预算按标题线索和全文位置分布选取；侧栏只保留已提交／可提取文字量、部分覆盖及提取限制的简要说明，不再提供“选中文字范围”详情或章节矩阵。100% 提交提取文字也不代表已读懂全文。[公开参考比较与已实现改动](docs/ENGINEERING-READING.md)说明 PaperQA、科学技能等参考的取舍与验证边界。
- 自由编辑阅读笔记；不再显示笔记下方的固定五项人工核对框，也不再自动保存这些框或在 Markdown 中生成固定核对清单。用户自行写在笔记中的 Markdown 复选项原样保留。
- OpenAI 兼容、Anthropic Messages、Google Gemini 与 Ollama 配置独立保存。启动、打开或切换论文不调用模型；AI 结果按论文和 PDF 附件保存，重开或再次点击 AI 分析会直接复用缓存。只有“重新分析”显式请求新结果。
- 可查看、完整编辑及恢复默认的三个提示词：分析系统提示词、多片段综合指令、论文对话系统提示词。每次实际系统提示词还会附加相应任务的固定只读输出协议，编辑器可展开核对协议及拼接后的全文。保存提示词不调用模型，也不使旧缓存失效；如需应用到已有分析，请显式重新分析。[默认全文与结构要求](docs/AI-PROMPTS.md)可供核对。
- 用户消息同时携带明确任务及同一份冻结的有效提示词，以兼容代理对 system 字段的不同处理；重复提示词会增加输入用量。Anthropic 与 Gemini 输出额度均为 8192 token，本轮不提高；解析失败、结构错误与服务截断分别提示。
- 对当前论文 PDF 提问，只有点击发送才提交问题、有限历史及有界原文片段；成功问答及通过校验的来源按论文和附件保存到本地。切换或加载历史不调用模型；无有效来源的回答会标记“未核验／信息不足”。
- 论文对话可在明确确认后清空当前 PDF 的已保存历史；不调用模型，后续提问不再携带该历史。其他 PDF、论文、分析、笔记、阅读状态与配置保留。同论文有对话请求进行时须先等待或取消；备份、导出文件及已创建的 Zotero 笔记不在清空范围内。
- 显式创建新的 Zotero 分析笔记，或将阅读记录保存为个人库中的插件专用状态笔记。

模型推断需要逐项核对；“引文逐字匹配”只表示文字存在于本次提取文本及所标页中，不证明该引文支持结论。图表引用也可能只提到图号而未识别图像。**只有读者可以确认已通读或已完全核查**；覆盖了全部提取文字也不代表读懂全文。

本轮界面精简沿用现有提示词、输出协议及 `readingGuide` 等数据字段，不刷新旧缓存，也不构成模型阅读质量提升的验证。

## 安装

开发分支的新工作区尚未进入 Releases；可从源码构建，或下载相应 commit 的 CI 工件。以下手动安装步骤也适用于本地开发包。

1. 从[本仓库 Releases](https://github.com/wuxinxin27/zotero-reading-room/releases) 下载版本对应的 `.xpi` 和 `SHA256SUMS`；若尚无发布，可按下面的命令自行构建。
2. 核对 SHA-256。例如 Windows PowerShell：`Get-FileHash .\zotero-reading-room-0.2.0.xpi -Algorithm SHA256`，与 `SHA256SUMS` 中该文件一行比较；Linux 可用 `sha256sum -c SHA256SUMS`。
3. 在 Zotero 选择 **工具 → 插件 → 从文件安装插件…**（Tools → Plugins → Install Plugin From File，部分版本在齿轮菜单），选择 `.xpi`，按 Zotero 提示完成。
4. 在 Zotero 中打开 PDF，使用阅读器工具栏或工具菜单中的“论文阅读室”入口聚焦右侧栏；也可从所选文献或 PDF 的右键菜单打开其正常 PDF 阅读器。缺少匹配 PDF 或 Reader 尚未就绪时不挂载阅读室，不改用同论文的其他附件。

本版本通过 Releases 分发，首次手动安装 `.xpi`。Zotero 10 要求清单声明更新地址；构建同时生成带版本、下载地址和 SHA-256 的 `updates.json`，由 Release 提供。更新检查服从 Zotero 自身设置；跨版本自动升级流程尚待独立验证。不同 Zotero 版本的菜单名称可能略有差别。

## 模型设置、提示词与当前论文对话

独立“模型设置”提供 OpenAI 兼容、Anthropic Messages、Google Gemini 和 Ollama 原生四种协议，端点可填写 base URL 或相应旧版完整请求地址。协议与端点及自动模型发现由后端统一处理，详见 [API 提供商说明](docs/API-PROVIDERS.md)。默认协议为 OpenAI 兼容，默认基础地址为 `http://127.0.0.1:11434/v1`，分析请求使用其 `/chat/completions` 路径，也接受旧版完整请求地址。

只有在主动打开“模型设置”后才自动获取模型列表。地址、协议或密钥变化后约 700ms 发起发现；旧请求会取消，迟到结果不会覆盖新配置。列表支持搜索与手工模型 ID。没有列表接口、鉴权失败、超时或空列表时，界面会说明原因并允许继续手工填写；插件不内置“可用模型”名称，也不安装、启动或下载模型。

本机端点可直接发现模型。远程 HTTPS 端点获取模型列表需单独勾选许可，该请求不发送 PDF 或论文正文。开始模型分析还需另一项明确同意，才发送有界原文片段及页位置；群组文库禁止远程正文分析。远程许可同时绑定 origin 与 provider；更改任何一项都会撤销旧许可和未提交密钥。密钥默认不保存；用户明确勾选后，才用 Zotero `OSKeyStore` 加密，并将密文放入 `Services.logins`。侧文件只保存非秘密配置，界面只显示是否已有密钥，不显示明文。

远程正文分析与对话必须使用 HTTPS，并勾选明确同意发送论文文本；群组文库在此版本中禁止远程正文分析及对话，但可单独授权读取模型列表。分析选取最多 120000 个原文字符，独立摘录按每包最多 16000 字符、最多 12 包发送；一个包可以含多个物理页，不再按前 12 页/片段截断。超预算选取是启发式，实际遗漏会记录。多包另有一次综合，输入最多 48000 字符，其中最多 48 条、共 28000 字符已匹配引文及关联发现。仅正文 JSON 格式错误会以同一任务和来源附加固定格式提醒，最多重新生成一次；每个失败的阅读包、综合阶段或问答可能因此多一次模型调用及费用，不增加审稿模型。鉴权、网络、截断、拒答、工具调用、安全和结构校验等其他失败不自动重试，详见[输出边界](docs/API-PROVIDERS.md#输出解析与固定错误)。API 密钥在请求时使用内存中的解密值；选择记住后只保存系统加密密文，不写入插件状态或仓库。本地模型服务也可能有自己的日志与联网行为，请按其设置判断。

已保存的自定义提示词不会被新默认覆盖。需要新默认时，先自行备份，再在提示词设置选择“恢复默认”并保存（会重置全部三项）；对已有结果显式选择“重新分析”才使用新流程与设置，无需删除缓存。新工科流程目前通过的是合成来源及服务回归；本轮真实论文、实际模型成功率和学术质量仍待验证，见[验证记录](docs/TESTING.md)。

论文对话不需要先完成 AI 分析。每次发送最多 6000 字符的问题，选取至多 8 段、共 24000 字符的提取文字，并附最近至多 10 条、共 12000 字符的历史消息；历史不是原文证据，也不代表全文上下文。失败或取消不追加半对问答。模型按服务商规则计费，重新分析、对话及自定义长提示词都会增加请求或 token 用量；上述字符边界不是 token 预算或费用保证。不要在提示词、问题或笔记中填写密钥。

启动插件、打开阅读室、切换论文和查看已保存分析均不发起模型请求，也不要求模型配置。无密钥的本机端点可匿名分析。详见[隐私说明](PRIVACY.md)。

## 数据保存与卸载

默认状态位于 **Zotero 数据目录下的 `reading-room/state-v1.json`**，按文库 ID 和条目 key 关联；笔记、三个提示词、AI 缓存、标签同步结果与按 PDF 附件区分的成功对话也在其中。旧 `checklist` 字段为兼容保留，不迁移或清理；JSON 导出和显式原生状态笔记快照仍可包含该字段。保存时保留上一份 `.bak`，临时写入文件为 `.tmp`。这些文件可能包含你的问题、笔记、原文摘录和模型结果，请像文库一样保护及备份。插件没有自己的云同步服务，这些侧文件内容不会随 Zotero 自动跨设备合并。

清空当前 PDF 对话只删除当前侧文件中的对应历史；原子保存保留的上一份 `.bak` 可能仍含清空前内容，外部备份、导出和 Zotero 笔记也不受影响。这不提供安全擦除保证。

旧侧文件中的关注字段及后端旧目录、批量 API 仅为兼容保留，当前界面没有入口，也不会在后台触发。本轮不迁移、删除或清理旧数据。

手动阅读状态先在本地保存，再尝试向父条目写入五个保留标签中的当前一个，移除另外四个；普通标签、其他 `阅读室/` 标签、题名等字段和原有笔记均保留。个人库及有编辑权限的群组库可写此标签；只读、未保存编辑、接口或保存失败会保留本地状态并提示未同步，可再次选择状态重试。标签可按 Zotero 自身设置跨设备同步；插件目前不会从原生标签自动恢复或双向合并本地状态。

“保存为新的 Zotero 分析笔记”仅在点击后创建插件分析笔记，同一份分析不重复创建。“同步阅读记录到个人库笔记”是**显式保存状态快照**，只会创建或更新本插件在当前个人库条目下创建并关联的专用笔记；如果该笔记被手动修改，插件停止覆盖并提示冲突。它不是自动双向同步或自动恢复机制。Zotero 自身的同步设置可能使这些笔记同步到你的 Zotero 账户。

除上述手动状态标签外，插件不改父条目字段，不覆盖你原有的 Zotero 笔记，不向群组文库写入笔记。卸载不会自动删除本地状态、保留标签或已创建的 Zotero 笔记；如需清理，先导出和备份，再由你手动处理插件专用文件、标签与笔记。

## 首版边界

- 不含 OCR。扫描件、加密或损坏的 PDF 可能无法提取文字；此前独立工作区的 PDF.js 和页预览记录不代表本轮原生侧栏已验收，侧栏布局、宿主生命周期与其他宿主版本仍需实测。
- 页码依赖宿主 PDF worker 返回的分页分隔符与提取页数一致；无法核实时显示未知页码。PDF 页序与印刷页码也可能不同。
- 内联原页预览用于核对文字引用，不裁切精确定位；模型不理解图像，也不能据此确认图注或验证图表视觉数值。后端图表文字候选及其校验、缓存和 JSON 导出保留，候选不等于核实了参考文献或真实引用关系。
- 模型按片段处理，可能截断、遗漏跨片段关系，也会出错。网络失败、取消或无文本时应保留此前已保存的状态。
- 默认本地状态不会自动跨设备合并；个人库专用笔记只提供显式快照，原生状态标签按 Zotero 设置同步。群组标签写入取决于编辑权限，群组笔记写入和远程正文请求仍被拒绝。

## 从源码构建

需要 **Node.js 22 或更新版本**，没有 npm 运行时或开发依赖，无需 `npm install`。

```sh
npm test
npm run check
npm run build
```

产物：`dist/zotero-reading-room-0.2.0.xpi`、`dist/SHA256SUMS` 和 `dist/updates.json`。构建将 `addon/` 内的运行时源文件放在标准 ZIP 根目录，固定文件顺序、时间戳和权限；相同源文件产生相同字节。文档、测试、用户数据、缓存与密钥不进入 XPI。构建会拒绝缺失文件、软链接、非源文件、版本或插件 ID 不匹配。

公开测试只使用[虚构样例](tests/fixtures/)。不要提交真实文库、个人路径、论文标题、正文、截图、笔记或密钥。贡献前请阅读 [CONTRIBUTING.md](CONTRIBUTING.md)，功能与分发计划见[路线图](docs/ROADMAP.md)。
