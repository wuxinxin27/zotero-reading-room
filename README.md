# Reading Room · 论文阅读室

[English](README.en.md) · [隐私](PRIVACY.md) · [安全](SECURITY.md) · [开发与测试](docs/DEVELOPMENT.md)

面向 Zotero 10 的本地优先论文阅读插件：记录阅读进度，用可回查的原文候选组织预读，并把“程序完成分析”和“自己读懂论文”分开。

当前版本为 **0.2.0，实验版**。声明兼容范围为 Zotero 10.0–10.*，初始验证目标为 **Zotero 10.0.7**；自动测试使用虚构文库适配器，不能替代 Zotero 实机验证。实机项目见[验证清单](docs/TESTING.md)。本项目尚未声称收录于 Zotero 官方插件目录。

## 可以做什么

- 五种人工选择的阅读状态：**未读 / 待读 / 在读 / 已读 / 搁置**。运行预读不会自动标记“已读”。
- 查看当前条目的作者、年份、来源、DOI、本地 PDF 可用性，以及 Zotero 笔记和注释数量；记录本地阅读笔记和核对清单。
- 离线“抽取式预读”：按词语线索归类原文摘录，覆盖**研究问题、新颖性、贡献、与前人工作的关系、优势与适用边界、技术独特之处**六个维度；贡献附理论、算法、实验和工程线索。
- 展示章节、术语、图表文字引用和引用上下文**候选**。证据可打开对应 PDF；页边界不可靠时不猜页码。
- 可选调用 OpenAI 兼容、Anthropic Messages、Google Gemini 或 Ollama 原生 API；从端点自动获取模型列表，也可手工填写模型 ID；查看覆盖范围、未验证引文与限制；显式导出本地 JSON / Markdown。
- 显式创建新的 Zotero 分析笔记，或将阅读记录保存为个人库中的插件专用状态笔记。

抽取式候选是低置信度检索线索，不能据此宣布论文有创新、优于前人、证明正确或真正支持某引用。模型推断也需要逐项核对；“引文逐字匹配”只表示文字存在于本次提取文本中。**只有读者可以确认已通读或已完全核查**；覆盖了全部提取文字也不代表读懂全文。

## 安装

1. 从[本仓库 Releases](https://github.com/wuxinxin27/zotero-reading-room/releases) 下载版本对应的 `.xpi` 和 `SHA256SUMS`；若尚无发布，可按下面的命令自行构建。
2. 核对 SHA-256。例如 Windows PowerShell：`Get-FileHash .\zotero-reading-room-0.2.0.xpi -Algorithm SHA256`，与 `SHA256SUMS` 中该文件一行比较；Linux 可用 `sha256sum -c SHA256SUMS`。
3. 在 Zotero 选择 **工具 → 插件 → 从文件安装插件…**（Tools → Plugins → Install Plugin From File，部分版本在齿轮菜单），选择 `.xpi`，按 Zotero 提示完成。
4. 选择一条文献或它的 PDF，使用工具菜单、条目右键菜单或条目面板中的“论文阅读室”入口。缺少本地 PDF 时，仍可编辑阅读状态和笔记。

本版本通过 Releases 分发，首次手动安装 `.xpi`。Zotero 10 要求清单声明更新地址；构建同时生成带版本、下载地址和 SHA-256 的 `updates.json`，由 Release 提供。更新检查服从 Zotero 自身设置；跨版本自动升级流程尚待独立验证。不同 Zotero 版本的菜单名称可能略有差别。

## 先离线使用，再决定是否调用模型

“抽取式预读”只在点击后使用 Zotero 的 `PDFWorker.getFullText` 读取已在本机可用的 PDF，不自动下载附件，也不调用模型。

“AI 分析…”提供 OpenAI 兼容、Anthropic Messages、Google Gemini 和 Ollama 原生四种协议，端点可填写 base URL 或相应旧版完整请求地址。协议与端点及自动模型发现由后端统一处理，详见 [API 提供商说明](docs/API-PROVIDERS.md)。默认协议为 OpenAI 兼容，默认端点 `http://127.0.0.1:11434/v1/chat/completions` 保持旧版本地服务兼容。

只有在主动打开 AI 设置后才自动获取模型列表。地址、协议或密钥变化后约 700ms 发起发现；旧请求会取消，迟到结果不会覆盖新配置。列表支持搜索与手工模型 ID。没有列表接口、鉴权失败、超时或空列表时，界面会说明原因并允许继续手工填写；插件不内置“可用模型”名称，也不安装、启动或下载模型。

本机端点可直接发现模型。远程 HTTPS 端点获取模型列表需单独勾选“允许连接该远程 API 获取模型列表”，该请求不发送 PDF 或论文正文。开始模型分析还需另一项明确同意，才发送有界原文片段及页位置；群组文库禁止远程正文分析。更改端点 origin 会撤销两项远程许可并清除保留的 API 密钥。密钥只保存在当前设置/请求内存中，插件不持久化。

远程正文分析必须使用 HTTPS，并勾选明确同意发送论文文本；群组文库在此版本中禁止远程正文分析，但可单独授权读取模型列表。分析请求发送有界的提取文字片段和页位置；当前上限为前 12 个片段、最多 120000 字符，实际覆盖可能更少。API 密钥只用于本次内存请求，不写入插件状态或仓库。本地模型服务也可能有自己的日志与联网行为，请按其设置判断。

启动插件、打开阅读室、查看状态均不发起模型请求。详见[隐私说明](PRIVACY.md)。

## 数据保存与卸载

默认状态位于 **Zotero 数据目录下的 `reading-room/state-v1.json`**，按文库 ID 和条目 key 关联；保存时保留上一份 `.bak`，临时写入文件为 `.tmp`。这些文件可能包含你的笔记、提取摘录和模型结果，请像文库一样保护及备份。插件没有自己的云同步服务。

“保存为新的 Zotero 分析笔记”仅在点击后创建插件分析笔记，同一份分析不重复创建。“同步阅读记录到个人库笔记”是**显式保存状态快照**，只会创建或更新本插件在当前个人库条目下创建并关联的专用笔记；如果该笔记被手动修改，插件停止覆盖并提示冲突。它不是自动双向同步或自动恢复机制。Zotero 自身的同步设置可能使这些笔记同步到你的 Zotero 账户。

插件不修改父条目元数据，不覆盖你原有的 Zotero 笔记，不向群组文库写入笔记。卸载不会自动删除本地状态或已创建的 Zotero 笔记；如需清理，先导出和备份，再由你手动处理插件专用文件与笔记。

## 首版边界

- 不含 OCR。扫描件、加密或损坏的 PDF 可能无法提取文字。
- 页码依赖宿主 PDF worker 返回的分页分隔符与提取页数一致；无法核实时显示未知页码。PDF 页序与印刷页码也可能不同。
- 图表功能只检索文字提及，不理解图像，不验证实验图、公式证明或代码实现；引用候选不等于核实了参考文献或真实引用关系。
- 模型按片段处理，可能截断、遗漏跨片段关系，也会出错。网络失败、取消或无文本时应保留此前已保存的状态。
- 默认本地状态不会自动跨设备合并；个人库专用笔记只提供显式快照。无群组写入与后台批量分析。

## 从源码构建

需要 **Node.js 22 或更新版本**，没有 npm 运行时或开发依赖，无需 `npm install`。

```sh
npm test
npm run check
npm run build
```

产物：`dist/zotero-reading-room-0.2.0.xpi`、`dist/SHA256SUMS` 和 `dist/updates.json`。构建将 `addon/` 内的运行时源文件放在标准 ZIP 根目录，固定文件顺序、时间戳和权限；相同源文件产生相同字节。文档、测试、用户数据、缓存与密钥不进入 XPI。构建会拒绝缺失文件、软链接、非源文件、版本或插件 ID 不匹配。

公开测试只使用[虚构样例](tests/fixtures/)。不要提交真实文库、个人路径、论文标题、正文、截图、笔记或密钥。贡献前请阅读 [CONTRIBUTING.md](CONTRIBUTING.md)，功能与分发计划见[路线图](docs/ROADMAP.md)。
